Mini Instagram (console)

A console-based Instagram built to teach OOP, SOLID, the Gang-of-Four design patterns and the high-level-design concepts from the course. It is a modular monolith with microservice-ready seams: one runnable process today, but every boundary that would become a network hop in real Instagram (database, message queue, cache, notification channel) is a real interface you can swap.

Prerequisites

  • A JDK 25 or newer. Built and tested on OpenJDK 26; sources target the Java 25 language level.

That is the only requirement. Maven itself is bootstrapped by the wrapper, so you do not need to install Maven.

The wrapper runs Java from JAVA_HOME (falling back to java on your PATH). If your default Java is older, point JAVA_HOME at a JDK 25+.

Build, test, run

Windows (PowerShell / cmd):

mvnw.cmd clean test      # compile + run the tests
mvnw.cmd exec:java       # run the console app
mvnw.cmd package         # build target/mini-instagram.jar
java -jar target\mini-instagram.jar

macOS / Linux:

./mvnw clean test
./mvnw exec:java
The first run downloads Maven and the dependencies; after that it works offline.

Project layout

src/main/java/com/miniinsta/   application code (package-by-bounded-context)
src/test/java/com/miniinsta/   tests
docs/                          concept guides (setup, architecture, patterns, HLD)

Learning path

The git history is the lesson. Each step-NN-* tag adds one concept on top of a build that already compiles, runs and passes its tests:

git tag                 # list the checkpoints
git log --oneline       # see the sequence
git checkout step-06-events   # jump to any point in the build

Documentation

  • docs/SETUP.html - install & tooling (JDK, Maven, JUnit, SQLite): what each is, why, how to use it.
  • docs/ARCHITECTURE.html - ports & adapters, bounded contexts, the event-driven write path, persistence.
  • docs/PATTERNS.html - SOLID + every GoF pattern, with the file and checkpoint where it lives.
  • docs/HLD.html - the high-level-design vocabulary (CAP, sharding, cache, message queue, ...) grounded in this code.
  • HANDSON.html - student worksheet: run / open / notice / do, per checkpoint.
  • students.html - your interactive hands-on deck: open it in a browser and follow along, one checkpoint at a time. Your progress is saved on your device.
  • The projector slide deck is provided separately by the instructor, outside this repo.
