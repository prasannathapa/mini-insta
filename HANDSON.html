Hands-on worksheet - Mini Instagram

Work through this with the instructor, one checkpoint at a time. For each step: checkout the tag, run it, open the named file, notice the idea, then do the short exercise. Everything is revertable with git checkout -- .

One-time setup

# you need a JDK 25 or newer: check with
java -version
# if it is older, point JAVA_HOME at a JDK 25+ (see docs/SETUP.md)

git clone <repo>            # or open the folder you were given
cd instagram
mvnw.cmd clean test         # Windows   (macOS/Linux: ./mvnw clean test)

Handy commands you will reuse:

git checkout step-06-events   # jump to a checkpoint
git checkout main             # back to the finished app
git checkout -- .             # undo your experiment on this checkout
mvnw.cmd exec:java            # run the app / that step's demo
mvnw.cmd test                 # run the tests

Checkpoint by checkpoint

step-01-scaffold - setup

  • Run: mvnw.cmd clean test
  • Open: src/test/java/com/miniinsta/MainTest.java
  • Notice: banner() was pulled out of main() so a test can call it. Logic you can call is logic you can test.
  • Do: add a second assertion that the banner contains the word console. Re-run the tests.

step-02-domain - SOLID, sealed types, records

  • Run: mvnw.cmd exec:java
  • Open: src/main/java/com/miniinsta/post/Post.java and Main.java
  • Notice: Post is sealed; the switch in Main.render has no default.
  • Do: in Main.render, delete the case TextPost branch and build. The compiler refuses (the switch is no longer exhaustive). Put it back. That is the safety net a sealed hierarchy gives you.

step-03-ports - ports, adapters, Singleton (DIP, ISP)

  • Run: mvnw.cmd test
  • Open: user/UserRepository.java, user/InMemoryUserRepository.java, app/AppContext.java
  • Notice: the service depends on the interface; AppContext is the only place a concrete store is chosen.
  • Do: add a test method to UserRepositoryContract that saving two users makes findAll() size 2. Run it. It passes for the in-memory adapter now, and will pass for SQLite for free at step 9.

step-04-services - services + Facade

  • Run: mvnw.cmd exec:java
  • Open: app/InstagramService.java
  • Notice: the console calls one class; follow(name) resolves a user in one context and writes an edge in another. requireLogin() guards actions.
  • Do: add a facade method myFollowerCount() that returns the follower count of the current user (use the graph service). You do not need to touch any other file.

step-05-factory - Factory

  • Run: mvnw.cmd exec:java
  • Open: post/PostFactory.java and post/PostType.java
  • Notice: one exhaustive switch maps a PostType to the right subclass.
  • Do: add a value REEL to PostType but do NOT add a factory case. Build. The compiler points at the exact switch to fix. Revert.

step-06-events - Observer / EventBus

  • Run: mvnw.cmd exec:java
  • Open: app/AppContext.java (the eventBus.subscribe(...) lines) and platform/events/EventBus.java
  • Notice: PostService publishes PostCreated and does not call the feed, notification or search code directly.
  • Do: add a fourth subscriber in AppContext: eventBus.subscribe(PostCreated.class, e -> System.out.println("[audit] post " + e.postId())); Run, sign in, post, and watch your line fire. No other file changes.

step-07-adapter - Adapter

  • Run: mvnw.cmd exec:java
  • Open: notification/channel/ (the interface, the console channel, the two adapters)
  • Notice: email and SMS wrap third-party APIs with different shapes; the console channel needs no adapter.
  • Do: write a LoggingNotificationChannel implements NotificationChannel that prints, and wire it in AppContext in place of the console channel. Run.

step-08-feed - Strategy + fan-out on write

  • Run: mvnw.cmd exec:java, sign in as alice, use menu 1 (feed) and 12 (toggle ranking)
  • Open: feed/EngagementFeedStrategy.java
  • Notice: swapping the strategy reorders the same feed; nothing else changes.
  • Do: change the like/comment weights in EngagementFeedStrategy, re-run, and see the order shift.

step-09-sqlite - persistence, normalization, contract tests

  • Run: mvnw.cmd exec:java -Dmini.store=sqlite, register a user, exit, run again.
  • Open: src/main/resources/schema.sql and post/SqlitePostRepositoryTest.java
  • Notice: your user persists across runs; the same contract test runs on SQLite; the schema has denormalized like_count / comment_count / feed alongside the normalized tables.
  • Do: find the denormalized columns in the schema and explain to a neighbour what keeps them correct (hint: PostService.like).

step-10-extras - stories, search, DMs

  • Run: mvnw.cmd exec:java, post something with #tags, then search (menu 5)
  • Open: search/Hashtags.java and story/Story.java
  • Notice: search is filled by observing PostCreated; a story expires 24h after posting, checked against an injected clock.
  • Do: change LIFESPAN in Story.java to Duration.ofMinutes(1) and look at StoryServiceTest - why does the test still pass without waiting?

step-11-cache - read-through cache

  • Run: mvnw.cmd exec:java
  • Open: feed/FeedService.java (the feed(...) method)
  • Notice: a cache miss builds and stores; a new post invalidates the affected feeds.
  • Do: add System.out.println("cache miss for " + viewerId); in the miss branch. Run, view a feed twice: the message prints once.

step-12-app / v1.0 - the whole app

  • Run: mvnw.cmd exec:java
  • Open: ui/ConsoleGateway.java
  • Notice: the gateway only ever calls InstagramService (the facade); it has no business logic.
  • Do: sign in, follow @alice, view your feed, post, like a post, send a DM (menu 9). Then find where each of those becomes one facade call.

Stretch exercises (take-home)

  1. Add SqliteStoryRepository (mirror the other SQLite adapters) and a StoryRepositoryContract run against both adapters.
  2. Add a ReelPost type and let the compiler show you every place to update.
  3. Add a CompositeNotificationChannel that delivers to console AND email.
  4. Add a UserFollowed event, and a notification when someone follows you.
  5. Private accounts. Add an isPrivate flag to User; make follow on a private account create a pending request that must be approved; make feed and profile reads check that the viewer is the owner or an approved follower. This turns "authorization" into a real, tested feature.
  6. Sketch a ShardRouter behind UserRepository that routes by id % N to one of N databases, and note which query becomes hard (hint: the social graph).
